# Vent Controller v4.4.2 (ESP32 / PlatformIO / Arduino)

Контроллер приточно-вытяжной установки с рекуператором/электронагревателем,
4 комнатами (CO₂ + заслонка), контуром давления вентилятора, датчиком загрязнения фильтра,
MQTT/Home Assistant, веб-UI с графиком давления и настройкой MQTT, и OTA.

Версия 4.4.2 — дополняет v4.4.1:
- **Датчик загрязнения фильтра** (перепад давления на фильтре, 4–20 мА, канал 2 ADS1115):
  - скользящее среднее (5 отсчётов), опрос раз в 10 с;
  - авария при превышении порога `filter_alarm_threshold` (300 Па) дольше 60 с;
  - MQTT-топик `vent/filter/state`, команда `set/filter_alarm_threshold`,
    сброс аварии через веб-UI (команда `reset&target=filter`);
- исправление версии прошивки в заголовке README.

## 1. Аппаратная часть

| Назначение | Пин(ы) | Примечание |
|---|---|---|
| Сервоприводы заслонок (4 комнаты) | 13, 14, 27, 26 | ШИМ 50Гц, калибровка импульса в NVS |
| Реле нагревателя (5 ступеней) | 4, 16, 17, 5, 18 | активный уровень HIGH |
| ШИМ вентилятора | 25 | LEDC, 1 кГц, 10 бит |
| 1-Wire (DS18B20 ×2: улица/приток, две отдельные шины) | 15, 32 | до 3 датчиков на каждую шину, адреса определяются при каждом запуске, проверка валидности и усреднение значений |
| I2C (ADS1115: давление + расход + фильтр 4-20мА) | SDA 21, SCL 22 | адрес 0x48, шунт 160 Ом |

Датчики 4-20мА подключаются через резистивный шунт 120 Ом на входы ADS1115:
- канал 0 — перепад давления (вентилятор);
- канал 1 — расход воздуха;
- канал 2 — перепад давления на фильтре (загрязнение).

## 2. Логика работы (сводка v2)

### Общее
- Установка **всегда стартует выключенной** после включения питания/перезагрузки,
  независимо от состояния до сбоя — ждёт явной команды `vent/set/power=1`.
- Аварии `heater_fault`/`fan_fault` **персистентны** в NVS: переживают reboot,
  сбрасываются только явной MQTT-командой.
- Ручной режим заслонок и сервисный режим **не персистентны** — сбрасываются
  при каждой перезагрузке.

### Заслонки / CO2 (на комнату)
- PI-регулирование по CO2 с зоной нечувствительности `co2_deadband` (100 ppm).
- Надбавка фрикулинга (temp_mode) с deadband `temp_freecool_deadband` (2°C) —
  надбавка не пересчитывается, если изменение (T_room − T_target) меньше deadband.
- **Аварийный форсаж**: CO2 ≥ `co2_alarm_threshold` (3000 ppm) → заслонка
  принудительно в `max_pos` (если ручной режим выключен).
- **Ручной режим** ограничен диапазоном `min_pos…max_pos`.
- **Приоритет ручного режима** (v4.2): если ручной режим включён, позиция
  заслонки всегда = `manual_pos` — **выше** CO2-форсажа и отсутствия данных
  (кроме случая выключенной установки).
- **Сервисный режим**: ограничение снято, угол задаётся напрямую (0–180°).
- `min_servo_step` (10°) — привод не двигается, если изменение меньше этого угла.
- Нет свежих данных CO2/температуры дольше `room_data_timeout` (10 мин) →
  заслонка идёт в `min_pos` (если ручной режим выключен).
- При выключенной установке (`power=0`) — все заслонки безусловно в `min_pos`
  (ручной режим игнорируется).
- Данные вне физического диапазона (CO2 0–5000 ppm, темп. комнаты −20…+50°C)
  считаются сбоем и не обновляют таймер свежести.

### Температурный режим (фрикулинг, temp_mode)
- Команда включения **игнорируется**, если уличная температура
  < `freecool_outdoor_min` (10°C).
- Если во время работы уличная температура опускается ниже порога — режим
  **автоматически выключается**.

### Вентилятор / давление
- **`dp_setpoint` вычисляется автоматически** (MQTT-команда прямого задания
  уставки удалена):
  ```
  dp_setpoint = dp_min + (dp_max − dp_min) × max(pos_1..pos_4)/100%
  ```
  где `max(pos_1..pos_4)` — максимальная фактическая позиция среди 4 заслонок
  (учитывает ручной режим и аварийный форсаж по CO2). Пересчёт — раз в 10 с,
  синхронно с циклом заслонок. Шаг обновления ограничен `min_dp_step` (10 Па).
- Регулирование ШИМ — PID по перепаду давления, шаг ограничен `min_fan_step` (5%),
  минимальная рабочая скорость `min_fan_speed` (5%, не касается полной остановки).
- **Последовательность включения**: сбор данных с датчиков и по MQTT →
  позиционирование заслонок → задержка `damper_settle_time_s` (15 с) →
  плавный разгон вентилятора `fan_ramp_time_s` (10 с) → рабочий режим (PID).
- **Последовательность выключения**: команда `power=0` → вентилятор переходит
  в режим выбега (`STOPPING`, PWM=0) на `fan_coastdown_time_s` (3 мин),
  заслонки удерживают текущую позицию → после завершения выбега вентилятор
  останавливается (`OFF`), затем заслонки закрываются в `min_pos`.
- **Аварии давления** (флаг `fan_fault`, отдельный от `heater_fault`, latched):
  - `dp < dp_alarm_low` дольше `dp_low_timeout` (180 с, в любой момент работы) → FAULT;
  - `dp > dp_alarm_high` дольше `dp_high_timeout` (20 с) → FAULT;
  - **пропадание показаний датчика давления** (обрыв 4-20мА/<3.5мА или NaN)
    на фазах 1–4 дольше короткого грейса `sensor_grace_s` (3 с) → FAULT
    **`SENSOR_LOOP`** без долгого «молчания» на 100% ШИМ;
  - во всех случаях — **мгновенный стоп** вентилятора (ШИМ → 0, без выбега) и
    **мгновенное** обесточивание всех реле нагревателя.
- Валидация соотношения аварийных/рабочих границ **не выполняется** (ответственность
  настройщика).

### Датчик расхода воздуха (4-20мА)
- Порог `flow_alarm_threshold` в % от шкалы 4-20мА (по умолчанию 30%).
- Расход ниже порога → **блокировка нагревателя** (BLOCK, автоснятие).
- Обрыв токовой петли (<3.5 мА) → блокировка нагревателя (как отказ датчика).

### Датчик загрязнения фильтра (перепад давления на фильтре, 4-20мА)
- Канал ADS1115: канал 2, скользящее среднее (5 отсчётов), опрос раз в 10 с.
- Порог `filter_alarm_threshold` (по умолчанию 300 Па).
- Превышение порога дольше `filter_alarm_duration_s` (60 с) → авария `filter_alarm_active`.
- Авария **не персистентна** — сбрасывается автоматически при нормализации давления,
  либо вручную через веб-UI / MQTT.
- Обрыв токовой петли (<3.5 мА) → датчик считается неисправным (`sensor_ok=false`).

### Нагреватель (5 ступеней)
Разрешён только при отсутствии всех условий блокировки:
- установка включена (`power=1`);
- `winter_mode=1`;
- нет свежих данных датчиков воздуховодов (приток/отток);
- уличная температура ≥ `heater_outdoor_block_temp` (18°C);
- фрикулинг разрешён (`temp_mode_enable=1`) хотя бы в одной комнате;
- вентилятор работает **не менее** `heater_min_fan_runtime_s` (3 мин) —
  таймер отсчитывается от начала разгона вентилятора;
- расход воздуха ≥ `flow_alarm_threshold`, датчик расхода исправен;
- фактическое давление в пределах `±dp_within_setpoint_pct` (20%) от `dp_setpoint`.

Ступенчатая логика (гистерезис): T_supply < target − `heater_deadband_low` (5°C) →
добавить ступень (не чаще раза в 60 с); T_supply > target + `heater_deadband_high`
(3°C) → снять ступень (не чаще раза в 5 с).

**Авария (`heater_fault`, latched)**: T_supply > `heater_alarm_temp` (60°C) →
мгновенно все реле OFF, ручной сброс.

При **любом** `fan_fault` — реле нагревателя обесточиваются мгновенно, синхронно
с остановкой вентилятора (без ожидания обычного 5-секундного таймера снятия ступени).

### FAULT — что публикуется
Код ошибки + значение соответствующего параметра на момент срабатывания:
- `heater_fault`: код + T_supply на момент срабатывания;
- `fan_fault`: код (1=низкое давление, 2=высокое давление, 3=нет датчика давления)
  + давление на момент срабатывания.

## 3. Дополнительные функции

1. Аварийный форсаж по CO₂ (3000 ppm) — см. выше.
2. Валидация данных (CO₂, температуры воздуховодов/улицы, температуры комнат) —
   значения вне диапазона не обновляют таймер свежести.
3. `heater_fault`/`fan_fault` персистентны в NVS, переживают reboot.
4. Установка всегда стартует в OFF.
5. DS18B20 читается неблокирующим способом (асинхронная конвертация ~750 мс).
6. Калибровка в NVS: импульсы сервоприводов (мкс), offset/scale датчиков 4-20мА —
   через веб-эндпоинты `/api/calibrate/servo` и `/api/calibrate/analog`.
7. Скользящее среднее (8 отсчётов) для давления и расхода воздуха.
8. Журнал событий — кольцевой буфер 50 записей в RAM, метки времени по NTP
   (UTC+3, без перевода часов), публикуется в `vent/log` (последние 15) и
   полностью доступен через `/api/log`.
9. Wi-Fi через WiFiManager, имя точки доступа при первой настройке — `Vent-Setup`.
10. mDNS: `vent.local`.
11. Сервисный тестовый режим (`vent/set/service_mode=1`) — прямое управление
    каждым реле (`vent/service/relay/<1-5>`) и сервоприводом
    (`vent/service/servo/<1-4>`), автосброс канала через 30 с без новой команды.
    Так же доступно из веб-интерфейса (вкладка «Управление»).
12. Экспорт/импорт всей конфигурации в JSON — `/api/backup` (GET) и
    `/api/restore` (POST), а также `vent/config/backup_request` /
    `vent/config/restore` по MQTT.
13. Версия и дата сборки прошивки — в `vent/state` (`fw_version`, `build_date`)
    и на веб-странице `vent.local`.
14. Страница «Управление» в веб-UI + `/api/ctrl` (см. раздел 5).
15. Коэффициенты PID вентилятора (Kp/Ki/Kd): хранение в NVS, настройка через
    веб-UI и MQTT (`set/dp_kp`, `set/dp_ki`, `set/dp_kd`).
16. Авария `SENSOR_LOOP` (код 3) при пропадании датчика давления на фазах 1–4
    с коротким грейсом `sensor_grace_s`.
17. Исправление конфликта LEDC-каналов серво и вентилятора
    (`FAN_PWM_CHANNEL ≠ 0/1/8/9`).
18. **Датчик загрязнения фильтра** (v4.4.2): перепад давления на фильтре (канал 2 ADS1115),
    скользящее среднее (5 отсчётов), опрос раз в 10 с, авария при превышении порога
    `filter_alarm_threshold` дольше 60 с, MQTT-топик `vent/filter/state`,
    команда `set/filter_alarm_threshold`, сброс аварии через веб-UI.

## 4. Дерево MQTT-топиков (корень `vent/`)

### Команды (`vent/set/...`)
`power`, `winter_mode`, `service_mode`, `co2_deadband`, `co2_alarm_threshold`,
`min_servo_step`, `room_data_timeout`, `temp_freecool_deadband`,
`freecool_outdoor_min`, `dp_min`, `dp_max`, `dp_alarm_low`, `dp_alarm_high`,
`dp_low_timeout`, `dp_high_timeout`, `min_fan_step`, `min_fan_speed`,
`min_dp_step`, `flow_alarm_threshold`, `dp_within_setpoint_pct`,
`dp_kp`, `dp_ki`, `dp_kd`,
`heater_target_temp`, `heater_deadband_low`, `heater_deadband_high`,
`heater_alarm_temp`, `heater_outdoor_block_temp`, `heater_min_fan_runtime`,
`heater_fault_reset`, `fan_fault_reset`,
**`filter_alarm_threshold`**.

> `dp_kp/dp_ki/dp_kd` — коэффициенты PID вентилятора (хранятся в NVS,
> применяются сразу и при следующем запуске).

### Команды на комнату (`vent/room/<1-4>/set/...`)
`manual_mode`, `manual_pos`, `co2_target`, `min_pos`, `max_pos`, `temp_target`,
`temp_mode`. Входные данные комнатных датчиков приходят по отдельным топикам:
`vent/room/<1-4>/data/co2` и `vent/room/<1-4>/data/temp`.
Пример: `vent/room/1/data/co2` с payload `650`, `vent/room/1/data/temp` с payload `22.5`.
Для совместимости также поддерживается старый топик `vent/room/<1-4>/data` с JSON `{ "co2": 650, "temp": 22.5 }`.

### Сервисный режим
`vent/service/relay/<1-5>` (0/1), `vent/service/servo/<1-4>` (угол 0-180).

### Состояние (публикуется, retained)
| Топик | Описание |
|-------|----------|
| `vent/state` | Общее состояние: `power`, `winter_mode`, `service_mode`, `fw_version`, `build_date`, `uptime_s`, `outdoor_temp` |
| `vent/room/<1-4>/state` | Состояние комнаты: `co2`, `temp`, `pos`, `max_pos`, `manual_mode`, `manual_pos`, `temp_mode`, `co2_fresh`, `temp_fresh`, `data_fresh`, `block_reason` |
| `vent/fan/state` | Вентилятор: `phase`, `pwm`, `dp`, `dp_setpoint`, `dp_min`, `dp_max`, `flow_pct`, `flow_sensor_ok`, `kp`, `ki`, `kd`, `fault_latched`, `fault_code`, `fault_dp_at_trip` |
| `vent/heater/state` | Нагреватель: `stage`, `t_supply`, `block_reason`, `fault_latched`, `fault_code`, `fault_temp_at_trip` |
| **`vent/filter/state`** | **Фильтр**: `pressure` (Па), `sensor_ok`, `alarm_active`, `alarm_threshold` |
| `vent/log` | Последние 15 записей журнала событий |
| `vent/status` | LWT-статус подключения (`online`/`offline`) |

### Конфигурация через MQTT
| Топик | Описание |
|-------|----------|
| `vent/config/backup_request` | Запрос полного бэкапа конфигурации (ответ в `vent/config/backup`) |
| `vent/config/restore` | Восстановление конфигурации из JSON (payload — JSON) |

`dp_setpoint` в `vent/fan/state` — **read-only** (вычисляемое значение),
прямой MQTT-команды для его задания больше нет.

## 5. Веб-интерфейс (http://vent.local)

### Вкладки веб-UI
- **Статус** — текущее состояние системы, таблица параметров по комнатам, график перепада давления (10 мин, обновление 3 с)
- **Управление** — вкл/выкл установки, зимний/сервисный режим, ручное позиционирование заслонок, фрикулинг и CO2 по комнатам, уставки давления, сброс ошибок, живые показания
- **MQTT** — форма настройки MQTT-брокера (сервер, порт, пользователь, пароль, Client ID, Root topic), сохранение в NVS + перезагрузка
- **Калибровка** — калибровка сервоприводов (pmin/pmax), датчиков 4-20мА (offset/scale), показ текущих значений и настройка коэффициентов PID вентилятора
- **Конфигурация** — экспорт/импорт JSON, просмотр журнала событий

### API эндпоинты
- `/` — главная страница с табами;
- `/api/status` — полный статус в JSON (включая `filter`);
- `/api/mqtt/config` (GET/POST) — чтение/запись настроек MQTT;
- `/api/ctrl?cmd=...` — команды управления: `power`, `winter`, `service`, `temp_mode`,
  `manual`, `manual_pos`, `co2_target`, `room_pos_limits`, `dp_limits`, `pids`, `reset`;
- `/api/calibrate/servo?room=N&pmin=..&pmax=..` (POST);
- `/api/calibrate/analog?sensor=dp|flow|filter&offset=..&scale=..` (POST);
- `/api/calib` (GET) — текущие значения калибровки (серво, датчики 4-20мА, фильтр);
- `/api/backup` (GET) / `/api/restore` (POST, тело — JSON);
- `/api/log` (GET) — полный журнал событий.

## 6. Первый запуск

1. Прошить контроллер. При первом старте (нет сохранённых Wi-Fi credentials)
   поднимется точка доступа **`Vent-Setup`** — подключитесь и укажите Wi-Fi сети.
2. Задать адрес MQTT-брокера можно двумя способами:
   - **До сборки**: в `include/Config.h` (`MQTT_SERVER`, `MQTT_PORT`, `MQTT_USER`, `MQTT_PASS`)
   - **Через веб-UI**: открыть `http://vent.local` → вкладка "MQTT" → заполнить форму → "Сохранить и перезагрузить"
3. Открыть `http://vent.local` — проверить статус, откалибровать сервоприводы
   и датчики 4-20мА через вкладку "Калибровка".
4. Через MQTT или веб-UI задать `winter_mode=1`, диапазоны `dp_min/dp_max`, целевые CO2 и
   температуру нагрева — после чего подать `power=1`.

## 7. Известные ограничения / что проверить при сборке

- Проект протестирован и собирается (`pio run`) на машине разработчика; целевой
  платформой является ESP32 (PlatformIO/Arduino).
- `ledcSetup/ledcAttachPin/ledcWrite` соответствуют API ESP32 Arduino core 2.x;
  на core 3.x потребуется переход на новый API `ledcAttach()`.
- Настройки MQTT сохраняются в NVS и применяются после перезагрузки. Для смены брокера
  достаточно обновить форму в веб-UI.
- ESPAsyncWebServer/AsyncTCP форки версий должны быть совместимы между собой —
  при ошибках линковки проверьте актуальные версии в `platformio.ini`.
- График давления использует Chart.js (загружается с CDN). Для работы требуется
  доступ к `cdn.jsdelivr.net` при открытии страницы (оффлайн-режим не поддерживается).
- **Датчик фильтра** (канал 2 ADS1115) должен быть подключён через шунт 160 Ом;
  порог аварии по умолчанию 300 Па, длительность превышения 60 с — параметры можно
  изменить через MQTT (`set/filter_alarm_threshold`) или веб-UI.
